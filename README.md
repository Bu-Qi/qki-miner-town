# QKI 矿工小镇

基于 QKI 的资源经营网页游戏，包含免费试玩矿区和通过智能合约记录进度的链上矿区。

## 功能

- 三类资源矿场：铜矿、能量、晶石；有限矿机分配与矿场升级。
- 五种制造配方、订单交付、成长徽章、矿队扩建和生产加速。
- MetaMask、TokenPocket 等 EVM 钱包连接，QKI 网络添加与切换，真实余额读取。
- 自动读取节点 Gas 报价，也支持自定义 gwei 单价；提交前展示费用估算。
- 链上操作经钱包确认，成功回执后重新读取合约数据；试玩存档单独保留。
- 响应式中文界面、原创 SVG 矿区地图、音效与减少动态效果设置。

## 本地运行

需要 Node.js 和 npm。本项目已在 Node.js 24 环境验证。

```bash
npm ci
npm run compile:contracts
npm test
python3 -m http.server 8080 --directory dist
```

打开 [http://localhost:8080](http://localhost:8080)。浏览器运行资源已包含在 dist 中，不依赖外部 CDN。资源使用相对路径，兼容站点根目录和 GitHub Pages 项目子目录。部署时发布 dist 目录的内容。

## 使用 QKI 链上矿区

1. 打开「链上」页面，连接 EVM 钱包。
2. 切换或添加 QKI 主网，Chain ID 为 20181205。
3. 连接已部署的同版本游戏合约，或通过钱包部署一份新合约。
4. 读取已有矿区，或确认交易创建该钱包的链上矿区。
5. 采集、合成、升级、订单等写入操作由钱包签名并支付 QKI 网络 Gas。

当前未内置已部署的主网合约地址。原游戏合约继续负责资源与积分，独立的 QKIRewardsVault 模块负责收款、赛季奖励和贡献分配；两者分别部署。材料、设备和积分是合约中的游戏数值，当前不提供 NFT 转出或兑换功能。

试玩进度保存在当前浏览器；链上进度按钱包地址记录，两者不会互相导入。链上记录不能通过试玩重置按钮清除。

## 合约与测试

合约使用 Solidity 0.8.38 编译，目标为 Petersburg EVM，并检查运行时代码大小。页面连接现有合约时会核对运行时代码哈希。

本地 Ganache 测试覆盖生产计时与前端规则一致性、资源扣除、重复订单拒绝、玩家数据隔离、矿机数量限制、钱包账户变更、网络切换、交易哈希恢复和拒绝直接充值。页面完整流程也已在隔离的本地 EVM 中验证。主网部署仍需使用者通过钱包执行。

## 奖池与活跃分配（v0.3）

外观销售的实际到账收入按 60% 赛季奖池、20% 活跃贡献分配、20% 运营收入划分；销售整数舍入余数计入运营。项目赞助 100% 进入当前赛季奖池，不可撤回，不产生投资份额。

每期七天。参与门槛为矿区创建满 24 小时、累计完成至少 10 张链上订单。先报名，再完成订单，并在截止前同步新增积分；报名之前的积分不计入。付费外观只改变角色头像，不增加产量、资格或奖励权重。

赛季前三名按 50% / 30% / 20% 分享赛季池；同分时较早报名者优先。活跃分配按每地址 min(本期已同步新增积分,1000) 除以全体权重分配。该门槛按地址计算，不是唯一真人或防机器人的保证。

结束后任何人可结算，玩家自行领取；领取也可以触发结算。历史权益不过期。空缺名次、无人参与的资金，以及全员领取后的整数分配余数，滚入后续开放赛季。运营地址只能领取实际计提的运营份额，不能提取玩家奖池。赞助、购买、报名和同步绑定预期赛季，跨期提交会回退。

使用方法：先连接游戏合约，再打开「奖池」，部署或连接 QKIRewardsVault。部署者为运营地址，金帽售价在部署时确定，页面默认建议 0.1 QKI，部署后不能修改。新模块不需要修改或迁移原游戏合约。

新增源码位于 dist/contracts/QKIRewardsVault.sol、dist/rewards-ui.mjs、dist/rewards.css；测试位于 tests/rewards.test.mjs。九项自动化测试覆盖分账、排名、领取、余额守恒、重复领取、重入与拒收、跨季、旧积分排除和钱包支付金额。页面支付流程已在隔离本地 EVM 验证。

当前发布的是页面与代码，主网奖池尚未由助手部署或注资，也未经过第三方独立审计。每笔实际支付与领取均需用户钱包确认，不承诺固定收益。


## GitHub Pages 部署

仓库的 Settings → Pages → Build and deployment → Source 选择 GitHub Actions。
`.github/workflows/pages.yml` 会在 main 分支的 dist 文件或该发布配置变更时自动发布，也可在 Actions 页面手动运行。
发布内容仅为 dist 目录，不需要安装依赖或重新编译合约。成功后的访问地址以 Pages 设置页和 Actions 部署输出为准。
